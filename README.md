HR Analytics & Employee Dashboard
A beginner-friendly HR analytics portfolio project built with Python, Pandas, Matplotlib, and SQLite SQL. The project analyzes synthetic employee profiles, monthly attendance, payroll, and employee exits. It creates a local SQLite database, generates visual reports, and exports summary metrics.
Synthetic-data and privacy notice: All employee names, IDs, salary figures, attendance records, and exit reasons are fictional sample data created for demonstration. They do not describe real people or a real organization. Do not use this project or its sample outputs to make employment decisions.

Repository information

GitHub description:
HR analytics project using Python, Pandas, Matplotlib, and SQL to analyze employee headcount, attendance, payroll, and attrition with automated charts and summary reports.

Project objectives
- Summarize total and active employees across departments.
- Analyze monthly attendance and absence patterns.
- Track monthly gross payroll, deductions, and net payroll.
- Explore synthetic employee exits by department and job level.
- Store the source datasets in a local SQLite database.
- Demonstrate SQL queries for common HR reporting questions.
- Generate charts and summary metrics automatically from CSV data.

Installation and execution
These steps are intended for Windows users running the project in Visual Studio Code.
Prerequisites
- Python 3.10 or later
- Visual Studio Code or another Python editor
- Internet access for the initial package installation
Step 1 — Download the project
Download the repository ZIP from GitHub and extract it, or clone the repository:
git clone https://github.com/YOUR_USERNAME/hr-analytics-employee-dashboard.git
cd hr-analytics-employee-dashboard
Replace YOUR_USERNAME with your GitHub username. If you downloaded a ZIP, open a terminal inside the extracted project folder instead.
Step 2 — Open the project in VS Code
1. Open VS Code.
2. Choose File → Open Folder.
3. Select the hr-analytics-employee-dashboard folder.
4. Choose Terminal → New Terminal.
Step 3 — Create a virtual environment (recommended)
In PowerShell:
python -m venv .venv
.venv\Scripts\Activate.ps1
If PowerShell prevents activation, use Command Prompt:
.venv\Scripts\activate.bat
You can also run Python from the environment without activating it, if needed.
Step 4 — Install dependencies
python -m pip install -r requirements.txt
Step 5 — Run the analysis
python hr_analytics.py
A successful run prints a completion message and record counts, creates hr_analytics.db in the project root, and writes charts and metric summaries into reports/.

Metrics and definitions
- Total employees in sample: Number of distinct employee IDs in employees.csv.
- Active employees: Number of distinct employees whose EmploymentStatus is Active.
- Synthetic exits: Number of distinct employee IDs in the attrition dataset.
- Synthetic exit share: Synthetic exits divided by all employee profiles, multiplied by 100. This is a simple sample-data indicator, not a formal HR attrition rate.
- Attendance rate: Sum of PresentDays divided by sum of WorkingDays, multiplied by 100. This is an aggregate rate weighted by recorded working days, not the average of employee-level attendance percentages.
- Annual gross payroll: Sum of GrossPayINR across the monthly payroll rows.
- Annual net payroll: Sum of NetPayINR across the monthly payroll rows.
Formal HR reporting may use different definitions. For example, an official attrition rate often requires a defined reporting period and average headcount denominator. Always document the chosen definition before comparing results.
SQL examples
The sql/analytics_queries.sql file contains SQLite-compatible examples to:
1. Count active employees by department.
2. Compare average annual salary across departments.
3. Calculate monthly attendance rate.
4. Summarize monthly gross payroll, deductions, and net payroll.
5. Count synthetic exits by department.
6. Calculate the overall synthetic exit share in the sample.
The Python program uses Python's built-in sqlite3 module to create and populate the local database. You do not need to install a separate database server. The SQL files document a schema and example queries; the Python script currently loads the CSVs directly into SQLite tables.
Data model
The intended logical relationships are:
- Employees.EmployeeID → AttendanceMonthly.EmployeeID
- Employees.EmployeeID → PayrollMonthly.EmployeeID
- Employees.EmployeeID → Attrition.EmployeeID
Employees is the employee profile table. Attendance and payroll are monthly fact tables. Attrition contains only the subset of synthetic employees marked as resigned.

The schema file documents primary and foreign key constraints. The Python script uses Pandas to_sql to rebuild the database tables from CSV data each time it runs, so the database produced by the script should be treated as a convenient analysis copy rather than a production-enforced database.
Troubleshooting
python is not recognized
Install Python, enable the option to add Python to PATH during installation, restart VS Code, and try:
py --version
py -m pip install -r requirements.txt
py hr_analytics.py
ModuleNotFoundError: No module named 'pandas' (or matplotlib)
Run this in the VS Code terminal:
python -m pip install -r requirements.txt
Confirm that VS Code is using the same Python interpreter where the packages were installed.
The reports folder looks empty
That is expected before running the script. Execute python hr_analytics.py and check the terminal for errors.
The SQLite database is not visible in GitHub
The generated database is intentionally ignored by .gitignore. It is created locally when the program runs. The source CSVs and SQL files are the reproducible inputs.
Limitations
- The data is synthetic and does not represent a real organization or workforce.
- Salary, attendance, and exit values are illustrative only.
- The project is a local analysis and reporting script, not a hosted web application or interactive dashboard.
- It does not implement authentication, authorization, or secure storage for real HR data.
- The generated charts describe the supplied sample and should not be interpreted as evidence about real employees.
- The SQL schema file is documentation/reference; the Python script recreates tables from CSVs when it runs.
